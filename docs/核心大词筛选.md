# 第二步：热门搜索词核心大词筛选

状态：新规则 `hot-search-core-v1` 已实现；旧规则继续兼容。真实 Seller Central 与付费模型联合验收尚待用户另行明确同意。

## 数据与候选

第一步 `product-term-v1` 已确认的全部商品词分别查询 Seller Central「品牌分析 → 热门搜索词」周报，读取搜索词与搜索频率排名。报告周固定为最近一个已结束周的周六结束日，按 UTC 日期判断，周六当天不算已结束；新模式省略 `week_end` 由后端确定，显式传入其他周会被拒绝。

搜索词按大小写、空白规范化去重，保留全部来源商品词。同周同词排名冲突直接失败，不取较优排名。只有 `search_frequency_rank <=250000` 进入分析，250,001 不进入。新规则不要求包含原词根，也不一律排除纯商品词。报告保留来源、周期、原始排名、采集时间、截断状态与诊断；截断结果只代表已取得范围。

## 四维相关度与意图

按任务站点、配送地区搜索，排除广告，按自然顺序去重 ASIN，最多取得前 30 个自然商品。用途、款式结构、规格由模型评分，价格由系统按可靠可比单价计算；权重固定为 35%、35%、20%、10%。单商品综合分严格 `>60` 才计入高相关，等于 60 不计入。

用途、款式结构或规格资料不足以及详情失败的商品同时退出分子和分母并保留原因。价格不能可靠归一时保留该商品，价格不参与综合分，前三维按 `35:35:20` 重新归一；价格可比时使用完整四维权重。搜索词相关度为 `高相关商品数 / 有效样本数 × 100%`；0 个有效样本为 `no_samples`，相关度为空，不按 0% 排名。20～30 个有效样本为高可信，10～19 为中，1～9 为低，可信度不改变阈值。采集与价格细则见 [商品词相关度分析](商品词相关度分析.md)。

精准意图独立判断，每项保存布尔值和中文理由：

1. `object_match`：购买对象一致。
2. `purpose_match`：核心用途一致。
3. `product_level_match`：完整商品主体一致，非附件、替换件、教程、原料或上级品类。
4. `modifiers_compatible`：明确限定属性相容；没有限定时通过。

四项全真且没有非精准事实才为 `exact`。非精准优先级固定为 `unrelated > accessory > broad`：类型、用途、结构或明确限定冲突优先 unrelated；无冲突但购买目标为附件则 accessory；指向包含本品的上级品类则 broad。未全通过且缺乏归类证据时保守为 unrelated。

品牌独立分类：只有 `generic` 可入选，`own_brand`、`competitor_brand`、`brand_unknown` 均仅作证据；自家品牌输入选填。

## 入选、排序与保存

同时满足 `ABA <=250000`、搜索词相关度严格 `>60%`、意图 `exact`、品牌 `generic` 才合格。单商品分数 >60 与词级相关度 >60% 是两道门槛。例如 30 个商品中 5 个无效，25 个有效商品中 16 个高相关，词相关度为 64%。

如果 ABA 排名 250,000 以内存在候选、但自动规则没有选出任何合格核心词，自动编排不再直接失败，而是在“核心大词”步骤暂停。页面列出本次分析中全部 250,000 以内候选及其相关度、意图、品牌和排除证据，允许运营人工勾选并保存；保存后流程从该步骤自动继续。人工兜底不能选择排名超过 250,000 的词。如果 250,000 以内本身为 0 条，则没有可供人工筛选的候选，流程仍停止并明确提示需要调整上游商品词后重新采集。

自动编排保存全部合格词，不截断到 10 或 20 个。人工可取消推荐或补选同一分析中已完成且合格的词，不能绕过门槛。当前请求/存储容量校验为 10,000 项。首次保存 `expected_version=0`，后续使用当前 version；相同分析、规则和集合复用原结果，旧版本冲突返回 409。

已选项优先，其余相关度降序、ABA 排名升序、规范化搜索词升序。前端默认每页 10 条，可选 5/10/20；分页仅影响显示，保存遍历全部选项。已选项仅在原表格稳定置顶，没有独立已选摘要框。

## 当前接口

基础路径为 `/api/v1/projects/{project_id}/pipeline-runs/{run_id}`。创建 POST 返回 200：首次为 queued；相同输入复用已有分析及其当前状态，不重新排队或执行。

| 方法 / 相对路径 | 行为 |
| --- | --- |
| `POST /aba-reports` | 新模式 `{"query_mode":"product_term","max_rows":1000}`；每路最多 10,000 行 |
| `GET /aba-reports`、`GET /aba-reports/{report_id}` | 只读历史；列表 offset 默认 0、limit 默认 5、最大 20 |
| `GET /aba-reports/{report_id}/hot-search-candidates` | 全部 ABA 入围候选数组 |
| `POST /hot-search-core-analyses` | `{"report_id":"UUID","own_brands":[]}` 创建或复用并激活当前分析 |
| `POST /hot-search-core-analyses/{analysis_id}/execute` | 显式执行已落盘 queued 分析，202；后台原子认领 |
| `GET /hot-search-core-analysis` | 任务当前采用的分析 |
| `GET /hot-search-core-analyses/{analysis_id}` | 指定分析及全部证据 |
| `GET /core-selection` | 当前确认及 stale |
| `PUT /core-selection` | `{"analysis_id":"UUID","rule_version":"hot-search-core-v1","candidate_ids":["UUID"],"expected_version":0}` |

POST 新分析只持久化排队。页面显式点击分析后依次创建、POST execute，再 GET 轮询；刷新仅恢复证据，未执行 queued 可点击“继续已排队分析”。execute 使用后台任务并通过服务原子认领，同一 ID 的 running 或终态不会重发。自动 LangGraph 在同步保存分析 ID 的 checkpoint 后调用同一 execute。

## 状态、恢复与费用

分析状态为 `queued/running/completed/incomplete/failed/stale`；逐词为 `waiting/running/completed/no_samples/failed`。单词失败不阻塞其他词，整体为 incomplete；全部词失败为 failed。采集截断也标记 incomplete。completed/incomplete 可保存其中已完成的合格词；queued/running/failed/stale 不可保存。

创建先保存输入快照、指纹、商品基准版本、规则、品牌、站点与配送地区，相同输入复用分析。执行只抢占 queued，running 和终态不重发。搜索、商品读取、意图、比较均有持久化调用记录。已明确收到结构错误的模型响应最多尝试 3 次；超时、网络中断或重启造成结果未知时不自动重复付费。

重启保留未执行 queued；遗留 running 或未决调用标为结果未知，未完成词记失败并汇总，不自动恢复付费调用。LangGraph 先同步写入报告与 queued 分析 ID 的 checkpoint，再执行下一节点；恢复先 GET 原 ID，仅 queued 可 execute。刷新、历史和轮询只读。

商品词选择、四维基准、报告内容或规则等输入变化后，历史分析显示 stale，禁止保存为当前选择；报告仍有效时可显式分析新输入。品牌输入变化产生不同指纹，切回原设置会激活原分析并复用证据。原报告日期不因刷新滚动。
